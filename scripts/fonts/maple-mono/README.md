# Maple Mono NL NFMono CN 自编译工程说明

本目录为工作站基准等宽字体（Maple Mono NL NFMono CN）的自编译构建基准源，由 GitHub Actions 自动化调度编译并托管至 assets 独立资产分支。

---

## 一、目录结构规范

```text
scripts/fonts/maple-mono/
├── config.json                     # 官方编译输入配置文件
└── README.md                       # 编译构建指令与偏离默认值的设计决策
```

---

## 二、一键编译执行命令

克隆上游官方仓库后，将本目录下的 `config.json` 覆盖至上游仓库根目录，执行如下双保险编译流水线：

```bash
# 1. 安装构建依赖
pip install -r requirements.txt

# 2. 触发自编译构建 (锁定 Regular / Bold / Italic / BoldItalic 核心工态字重)
python build.py \
  --cn \
  --cn-wenyuan \
  --nf \
  --nf-mono \
  --no-liga \
  --no-hinted \
  --ttf-only \
  --least-styles
```

> **构建产物命名机制**：由于启用了 `--no-liga` 与 `--nf-mono`，构建系统会自动装配出法定标准名称：
> - **系统识别全名**：`Maple Mono NL NFMono CN`
> - **紧凑文件名**：`MapleMonoNL-NFMono-CN-Regular.ttf`（涵盖 Regular, Bold, Italic, BoldItalic 四大核心工态字重）

## 三、偏离官方默认值的设计决策矩阵（Decision Log）

本字体的所有配置均围绕**“绝对等宽、零语义歧义、终端严格对齐、杜绝换行排版缺陷”**的最高工程标准定制：

### 1. 彻底禁用代码连字 (`enable_ligature: false` / `--no-liga`)
- **偏离理由**：默认的连字（如 `!=` 变 `≠`、`==` 与 `===` 变长横线）在代码审查中极易造成逻辑误读；在正则表达式或指针操作时产生干扰；在部分终端中会导致光标跳变或选择区域漂移。
- **最终形态**：保留纯正的 ASCII 原始物理形态，代码写什么即显示什么，绝对确定。

### 2. 选用文渊基字 (`--cn-wenyuan`)
- **偏离理由**：官方默认的资源圆体基字缺少全角拉丁小写字母 `ｍ` (`\uff4d`)。VSCode 探测全角字符时会以此为探针，缺失会导致其回退到系统字体度量，引发**长中文段落自动换行（Word Wrap）计算溢出窗口边界、折行错位**的缺陷。
- **最终形态**：文渊基字补齐了全角拉丁字符及度量表，彻底根治 VSCode 换行溢出缺陷。

### 3. 严格锁定 1:2 几何等宽 (`"cn.narrow": false`)
- **偏离理由**：官方提供的 `--cn-narrow` 会将中文字宽压缩至 1000。此时西文宽 600、中文宽 1000（比例变为 3:5 非整数倍），操作系统将直接把该字体剔除出等宽（Monospace）分类，造成终端无法识别、Markdown 表格边框完全错位崩塌。
- **最终形态**：强制保持西文 600、中文 1200 严格 1:2 几何对齐，保全 `isFixedPitch` 等宽标识。

### 4. 锁定单宽 Nerd Font 图标 (`"nerd_font.mono": true` / `--nf-mono`)
- **偏离理由**：默认的 Nerd Font 图标占用双列宽或变宽（Proportional），在终端状态栏（Oh-My-Posh, Starship, Lualine）输出目录、Git 分支图标时，极易导致后方文本被遮挡吞噬或列对齐错位。
- **最终形态**：所有图标严格限制为单字符宽度（600 单位），终端按列排版永不位移。

### 5. 全字符严禁微调 (`use_hinted: false`, `cn.use_hinted: false` / `--no-hinted`)
- **偏离理由**：中文字符笔画成千上万，微调会导致汉字笔画严重发黑粘连、字体体积膨胀 30% 以上；且在高分屏及现代 DirectWrite 亚像素抗锯齿引擎下，微调反而会导致字符边缘生硬畸变。
- **最终形态**：全字符禁用 TTFAutohint 字节码，还原纯净平滑的原始贝塞尔圆角曲线。

### 6. 特征冻结加固 (`feature_freeze`)
- **`cv01: enable`（符号规整）**：归一化 `@ $ & % Q => ->`，消除夸张圆角，回归规整严肃的工程几何风；
- **`cv04: ignore`（小写 l 保持原样）**：Maple Mono 默认的小写 `l` 本身就带有优雅的向右弯钩，清晰区别于数字 `1` 与大写 `I`；开启 `cv04` 反而会加上 Consolas 样式的突兀粗底座；
- **`cv09: ignore` 与 `cv10: ignore`（7 与 Z 不加腰线）**：数字 1 底部已有横线，与 7 不混淆；字母 Z 折角鲜明与数字 2 极易区分，不加腰线更干净美观；
- **`cv34, cv35, cv36: enable`（斜体去花体化）**：斜体彻底剔除 `k` 的花体小圆圈、`l` 的花体连笔尾以及 `x` 的上下卷翘小尾巴，呈现干净平直相交的现代工程印刷斜体；
- **`cv42: ignore` 与 `cv43: ignore`**：斜体 7 与 Z 同样保持无横线；
- **`cv61: enable`（直尾标点）**：逗号 `,` 与分号 `;` 的尾巴由圆弧改为平直斜线，在小字号下能一眼分辨半角英文标点与全角中文标点；
- **`cv96~cv98: ignore`（关闭全角引号与破折号）**：防范 Unicode 不确定宽度字符引发的严重终端 Bug（开启后部分终端后方字符会重叠在引号上，如 `“a` 重叠）；
- **`cv99: disable`（关闭居中标点）**：严禁开启繁体中文居中标点，确保简体中文全角逗号、句号精准位于左下角。

## 四、工作站自动化装配拓扑

本资产与工作站操作系统配置解耦自治：
- **装机冷启动**：由系统外壳加固脚本 `scripts/windows/shell.ps1` 闭环承接；
- **用后即焚零残留**：脚本直接嗅探 Windows 系统字体库，未就绪时从云端 `assets` 资产分支下载预编译 zip 至临时沙盒，静默安装注册至系统字体后彻底粉碎临时沙盒，本地磁盘零常驻负担；随后将 `Maple Mono NL NFMono CN` 注入 Windows Terminal 生产力底座。
